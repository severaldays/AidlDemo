## 1. 概述

本文档详细说明汽车座舱AI智能体系统的技术选型方案，包括各模块的技术选择、对比分析和最终决策依据。

### 1.1 选型原则

| 原则 | 说明 |
|------|------|
| **车规级适配** | 优先选择支持车规级芯片(8295)的技术方案 |
| **性能优先** | 满足实时交互的低延迟要求 |
| **稳定可靠** | 选择成熟稳定的技术方案 |
| **端云协同** | 支持离线能力，云端增强 |
| **可扩展性** | 便于后续功能扩展和升级 |

## 2. AI/LLM技术选型

### 2.1 端侧LLM选型

#### 2.1.1 候选方案对比

| 模型 | 参数量 | 内存占用 | 推理速度 | 中文能力 | 8295支持 |
|------|--------|----------|----------|----------|----------|
| **Qwen2-1.5B** | 1.5B | ~3GB | 优秀 | 优秀 | ✅ |
| **Gemma-2B** | 2B | ~4GB | 良好 | 一般 | ✅ |
| **Phi-2** | 2.7B | ~5GB | 良好 | 一般 | ✅ |
| **TinyLlama-1.1B** | 1.1B | ~2.5GB | 优秀 | 一般 | ✅ |
| **MiniCPM-2B** | 2B | ~4GB | 良好 | 优秀 | ✅ |

#### 2.1.2 推荐方案

**主选: Qwen2-1.5B**

选型理由:
- 中文语言能力出色，适合国内车载场景
- 参数量适中，8295芯片可流畅运行
- 阿里开源，持续更新维护
- 支持INT4/INT8量化，可进一步优化

**备选: MiniCPM-2B**
- 中文能力优秀
- 面壁智能开源，社区活跃

#### 2.1.3 端侧推理框架

| 框架 | 优势 | 劣势 | 8295优化 |
|------|------|------|----------|
| **llama.cpp** | 轻量、跨平台 | Android适配一般 | 需定制 |
| **MLC-LLM** | 多平台优化 | 部署复杂 | 支持 |
| **ONNX Runtime** | 通用性强 | LLM优化一般 | 支持 |
| **TensorFlow Lite** | Android原生 | LLM支持有限 | 优秀 |
| **QNN (Qualcomm)** | 8295原生支持 | 生态封闭 | 最优 |

**推荐: QNN + llama.cpp**
- 核心推理使用QNN利用8295 NPU加速
- llama.cpp作为模型加载和推理管理层

## 4. Multi-Agent框架选型

### 4.1 候选框架对比

| 框架 | 语言 | 车载适配 | 资源占用 | 可扩展性 | 文档 |
|------|------|----------|----------|----------|------|
| **LangChain** | Python | 需适配 | 高 | 优秀 | 优秀 |
| **AutoGen** | Python | 需适配 | 高 | 优秀 | 良好 |
| **CrewAI** | Python | 需适配 | 中 | 良好 | 良好 |
| **自研框架** | Java/Kotlin | 原生适配 | 低 | 完全可控 | 自建 |

### 4.2 框架选型决策

**推荐: 自研轻量级Agent框架 (参考LangChain/AutoGen设计)**

选型理由:
1. **性能**: Java/Kotlin原生实现，资源占用低
2. **适配**: 针对Android和车载场景优化
3. **可控**: 完全掌握核心逻辑，便于定制
4. **轻量**: 只实现必要功能，避免冗余

## 5. 车控技术选型

### 5.1 车辆通信协议

| 协议 | 用途 | 速率 | 实时性 |
|------|------|------|--------|
| **CAN** | 车身控制 | 1Mbps | 高 |
| **CAN FD** | 高速数据 | 8Mbps | 高 |
| **LIN** | 低速设备 | 20Kbps | 低 |
| **Ethernet** | 域控通信 | 100Mbps+ | 中 |

### 5.2 Android车控接口

| 接口类型 | 说明 | 推荐场景 |
|----------|------|----------|
| **AIDL** | Android标准IPC | 跨进程服务调用 |
| **HIDL** | HAL接口定义 | 硬件抽象层 |
| **Vehicle HAL** | 车辆属性接口 | Android Automotive |
| **直接CAN** | 底层总线访问 | 特殊需求 |

**推荐: AIDL + Vehicle HAL**
- 上层应用通过AIDL调用车控服务
- 车控服务通过Vehicle HAL访问硬件
- 符合Android Automotive架构规范
